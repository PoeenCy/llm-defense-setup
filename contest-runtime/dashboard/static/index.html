Two kinds of rule, two jobs. Suricata only detects (raises an alert in Events) — it watches a copy of the traffic and can never break your service. ctf_proxy actually blocks (drops the connection) — a too-broad rule here also blocks the checker bot and costs SLA. Workflow: load the attack from Tulip → select the malicious part → build a rule → test it on recent traffic to see what else it would hit → apply. Everything you apply is backed up and can be rolled back.
